# Methods mapping

This crosswalk separates the [ACL publication](https://aclanthology.org/2023.findings-acl.410/), [official artifacts at the pinned commit](https://github.com/SALT-NLP/codenames/tree/9bf4550e681f7a42ac406439b00b0c717f59f13c), and the current adapter. Upstream paths refer to unchanged files under `sources/upstream/`. Detailed findings are in [validation](validation.md); main-experiment choices remain in the [draft protocol](experimental_protocol.md).

## Task and information

| Item | Paper | Public artifacts | Current implementation / evidence | Remaining limits |
| --- | --- | --- | --- | --- |
| Prediction unit and success | §4.3 / Table 1 formulate binary intentional guessing success. An unplanned goal-word guess is not intentional success. | One target, its rationale and one output per CSV row. | Target-level classification: intended interpretation is whether that specified target was selected. | Original guesses and label-building code are absent; exact timing, membership and normalization rules cannot be recovered. |
| Multiple targets | §3.3 allows several target/rationale pairs per clue. | Shared-context rows can contain different targets and outputs. | Rows are treated as target-level examples, not whole-turn/game outcomes. | Without turn IDs, exact expansion and grouping cannot be independently verified. |
| Base input | Table 1 conceptually encodes unselected words, target/rationale and clue. | Literal order is `remaining: <list>, rationale: <text>, target: <word>, hint: <clue>`. | Uses the released `base_text` string. | Conceptual notation does not prove literal order, special-token registration or original game-state accuracy. |
| Personality input | §4.4 prefixes giver and guesser background attributes. | `GIVER: [<profile>], GUESSER: [<profile>], <base_text>`. | A uses base text; B uses the personality field. Profile grammar, parsed base components and full suffix equality are checked. | Prefixes change values, availability markers and length together; they do not isolate a causal personality effect. |
| Human/model information | §3.3, “Gameplay Attributes,” marks target words and target rationales as hidden from the guesser (printed p. 6552); §3.1 also states the rationale is not displayed. §4.3 supplies them to the classifier. | Target and giver rationale are in both model inputs; original guesses are not supplied. | Predicts success with privileged information, rather than reproducing the human guesser's information state. | Inclusion of task-defined inputs alone does not establish outcome leakage or human cognitive-process equivalence. |
| Personality values | §3.4 describes five dimensions; Appendix D.2.2 lists ten questionnaire items with -2..+2 answers. | Five numeric dimension fields per nonmissing role, observed at 0.0..4.0 in half steps; `[None]` denotes a whole missing profile. | Values and missing profiles are retained without imputation. | Item mapping, reverse scoring, aggregation and scale conversion are unverified. Zero is a value, not missingness. |
| Rationale normalization | §3.3 / Appendix B describe GPT-3 `text-davinci-003` normalization. | Raw rationales and per-row transformations are unavailable. | Uses official preprocessed strings unchanged. | Normalization was not reproduced or independently validated. |
| Split policy | §5 specifies 80/10/10 over clue givers, with a giver confined to one split. | Export indexes restart in each CSV; participant/game/turn IDs are absent. | Keeps released splits and checks exact row/input overlap. | String non-overlap does not establish giver/participant/game independence. Row proportions need not equal giver proportions. |

The hidden-information citation is §3.3 in the [preserved ACL version](../sources/paper/2023.findings-acl.410.pdf), not §3.2, which concerns board-word selection. Personality measures individual differences; it is not itself a measure of culture or shared knowledge. Nonmissing profiles use conscientiousness, extraversion, neuroticism, openness and agreeableness in that order.

## Models, settings and adapter differences

| Item | Paper | Public artifacts | Current implementation / evidence | Remaining limits |
| --- | --- | --- | --- | --- |
| Model identity | §5 / Table 5 use base RoBERTa. | `train_classification.sh` names `roberta-base-cased`; anonymous lookup returned HTTP 401. | Candidate `FacebookAI/roberta-base` tokenizer/config is pinned to `e2da8e2f811d1448a5b465c236feacd80ffbac7b` in [configuration](../configs/model_candidate.json). | Public resolution failure does not prove nonexistence. Exact original-checkpoint identity is unverified; adoption for the main experiment is still pending. |
| Reference comparison | Table 5 gives 0.57 without priors and 0.67 with Personality; §5 averages five runs. | Original seeds, run logs and checkpoints are unavailable. | Uses these as published reference values; plans five runs per condition. | No project A/B performance result exists; seeds and aggregation are not fixed. |
| Rate, duration and batch | Appendix E searches six classification rates, including 5e-6, and epochs 1-15. | Classification code fixes 5e-6, 25 epochs and batch size 32. | Records the discrepancy without adopting a research setting. | 5e-6 is within the search set; 25 epochs exceeds its stated range. Protocol choice remains open. |
| Label conversion | Binary outcome. | `1 if l else 0` follows CSV type inference. | `data.py` explicitly maps exact strings/native Booleans to 0/1 and rejects unexpected values. | Conversion is verified, not regeneration of original labels. |
| Metric | Table 5 reports Macro-F1. | `load_metric('f1')`, macro averaging. | `metrics.py` uses classes [0,1], macro averaging and zero_division=0; accuracy is separate. Known-answer tests passed. | Synthetic metric checks provide no research performance evidence. |
| Selection and Test | Exact classification selection details are not recoverable from the paper alone. | Generic `f1` key, epoch evaluation/save, best-model loading; named Validation and Test evaluation datasets. Public selector script handles generation tasks. | Development builder accepts Train/Validation only; `eval_validation_macro_f1` is checked explicitly. Final prediction is a separate API. | Research evaluation cadence, ties and stopping rules remain open. |
| Evaluation coverage | No recovered per-row execution evidence. | `dataloader_drop_last=True`. | Under the version/configuration documented in [validation](validation.md), stock synthetic evaluation/prediction omitted a case; adapter evaluation preserves the last batch independently of training. | Evidence is for one CPU process; other versions and distributed behavior are not established. |
| Tokenization | Exact operational maximum is not recovered. | `truncation=True` without an explicit maximum. | Pinned tokenizer/config capacity and Train/Validation content preservation are checked. | Final maximum, padding/truncation rules and Test tokenization remain protocol work. |
| Environment | Original software versions are unspecified. | No complete reproducible original environment. | [Pinned CPU environment](../environment/README.md) and a random tiny-model execution path are verified. | This is compatibility evidence; GPU execution and full-model resource requirements are unverified. |

Original strings, labels, splits and upstream code are preserved. Predictive comparison, causal explanation and cognitive-process claims remain distinct.
